## 2. Findings sorted by REVENUE IMPACT

### HIGH — revenue-affecting

#### H1. Pretty Links keyword auto-replace is silently injecting 1,720 affiliate anchors across all 23 posts

> **STATUS: RESOLVED 2026-04-28** — False positive. User verified in WP Admin → Pretty Links → Options that "Enable Keyword Replacements" is OFF. The 1,720 `pretty-link-keyword` class hits in rendered HTML are legacy CSS classes — either manually-inserted Pretty Link anchors written into `post_content`, or historical auto-replacements baked in before the toggle was turned off. Not active runtime injection. Per-link `_prli_keywords` postmeta exists as dormant data, not a runtime trigger when the global toggle is off. Logged as Bug #10 in `audit-script-bugs.md`: future audits must check `prli_options.link_replacement_type` (or absence) AND the class count to determine whether auto-replace is actually firing — class count alone is not a signal.

- **Evidence.** Every rendered post page contains `<a class="pretty-link-keyword" href="https://aistackscout.com/go/<X>">` anchors that are NOT in `post_content`. Counted across the 23 fetched HTML pages: 1,720 keyword-auto-injected `/go/` anchors total. Per post: 38 (pid 734) to 129 (pid 925).
- **Confirmation.** Buffer Pretty Link postmeta (ID 926) shows `_prli_keywords: "Buffer, AI social media tool, social media scheduling, Buffer AI"` — proves keyword auto-replace is configured per Pretty Link, and the Buffer entry alone matches roughly every article that uses the word "buffer" (figurative, not the tool) plus "social media scheduling" (any post mentioning social).
- **Why this is HIGH.** Three compounding revenue/compliance risks:
  1. The injected anchors carry no inline `(aff)` marker and no per-anchor disclosure context. FTC requires the disclosure to be near the anchor, not just at the top of the page.
  2. The rendered-page footprint includes `/go/buffer`, `/go/jasper`, `/go/publer`, `/go/instantly`, `/go/notion`, `/go/copyai`, `/go/writesonic`, `/go/surfer-seo`, `/go/chatgpt`, `/go/vista-social` appearing in articles that do not review those tools — e.g., the Jasper Review (pid 608) renders 84 keyword-replaced anchors, including ~7 distinct affiliate targets that have no editorial relationship to the article.
  3. Keyword auto-replace inside non-affiliate context can violate program rules ("not in cloaked or unrelated content"). Some networks treat this as a program-ban risk on its own.
- **Reference.** Pretty Links plugin v3.6.21, Code Snippets v3.9.5 active. `prli_options` shows `link_redirect_type=301`, `link_sponsored=1`, `link_nofollow=1` (good), but the keyword-replacement feature is plugin-level, not in `prli_options`. Verify via WP Admin → Pretty Links → Tools → Keyword Replacement (or per-link `_prli_keywords` postmeta).
